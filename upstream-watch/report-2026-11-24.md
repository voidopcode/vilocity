## Top PORT items

1. **VIctory: shader warm-up and pipeline pre-build from GTA VI's shader pack** (`c47b529`, `9c58a1c`, `286e33f`, `7389303`, `819f622`). Every shader is translated ahead of time and pipelines are built from the game's own pack. This is the biggest fix for GTA VI stutter on native.
2. **VIctory: FidelityFX, 64-bit image atomics, BVH intersection on the host, and title memory through a page table** (`0b35b7f`, `27c3dc9`, `0f63757`). This covers ray-tracing builders and tracers that read raw addresses, plus the console upscaler. It overlaps with the fork's `bvh.rs` and `emit/intersect.rs` already in native, so merge by hand.
3. **xcl: per-lane form and split wave64 on 32-lane waves** (about 50 commits, opt-in `XCL_PER_LANE=1` → `VILOCITY_PER_LANE`). wave64 code runs directly on RTX 32-lane waves. This is the owner's GPU case.
4. **xcl: direct RDNA2 → DXIL translator** (about 45 commits, opt-in `XCL_DIRECT_DXIL`). It skips HLSL and DXC, which cuts PSO compile time. Very large: about 25k lines in `gpu/dxil/`.
5. **xcl: link without high-entropy ASLR** (`02bfd1d`). A retail `XboxBvhBuilder` refuses acceleration structures at or above 2^40. This is a small fix for ray tracing on compat. Check native too: it has no such linker flag.
6. **xcl: D3D12.X stability and speed.** Wait64 cross-queue cycle fix, allocator Reset and Release fixes, sparse and reserved resources, the driver pipeline cache kept on disk and prebuilt, a cap on huge-PSO concurrency, and `PSO_WAIT_MS`.
7. **xcl: finest system timer** (`9507d05`) fixes choppy audio in the retail game. Native already does this (`vilocity-hle/src/runtime.rs`); compat does not.

Path rules used below: xcl `crates/xcl/src/…` → `compat/crates/vilocity-compat/src/…`; VIctory `crates/victory-X/…` → `native/crates/vilocity-X/…`, `apps/victory/…` → `native/apps/vilocity-native/…`; `XCL_*` / `VICTORY_*` env vars → `VILOCITY_*`. Both engines now use the `VILOCITY_` prefix, so check each new variable for name clashes when porting.

### 1. Per-lane form / split wave64 on 32-lane waves: **PORT** (high)
Lane-mask analysis and a per-lane lowering that runs wave64 programs on 32-lane hardware waves without whole-wave emulation. It covers VS/PS/compute, cross-lane ops, s_wqm/s_cselect/v_cmpx, far jumps, heap memory windows and coalesced guarded runs.
